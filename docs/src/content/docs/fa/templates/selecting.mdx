## چه چیزهایی قابل انتخاب‌اند

**هر پانزده تمپلیت اصلی قابل انتخاب‌اند.** فهرست بسته است: شناسه‌ای که در این فهرست نباشد
رد می‌شود، نه اینکه بی‌صدا با چیز دیگری جایگزین شود.

```
row  editorial  canvas  prism  terminal  pulse  brutal  arcade  sketch
signature  saffron  pulsenova  prismnova  terminalnova  arcadenova
```

**پیش‌فرض `row` است.** تنظیماتی که پیش از افزوده‌شدن انتخاب تمپلیت ساخته شده باشد، یا
شناسهٔ ناشناخته‌ای ذخیره کرده باشد، به `row` بازمی‌گردد و این را اعلام می‌کند.

## انتخاب کجا انجام می‌شود

**در نصب تازه**، نصب‌کننده خودِ طرح‌ها را پیشنهاد می‌دهد و از شما می‌خواهد یکی را برگزینید:

```
Choose your Row-Template design
  1  Row
  2  Editorial
  …
Select [1-15, Enter=Row]:
```

زدن Enter یعنی **Row**. تا خلاصه را تأیید نکنید چیزی اعمال نمی‌شود.

**پس از نصب**، از مدیر طرح را عوض کنید:

```bash
row-template
```

سپس **‏۲ Reconfigure → ‏۴ Template** را انتخاب کنید. این جابه‌جایی یک تراکنش کامل
عکس‌برداری/اعتبارسنجی/فعال‌سازی است، پس یک جابه‌جایی ناموفق طرح قبلی را برمی‌گرداند.

> **دستور `row-template config` تمپلیت انتخاب نمی‌کند.** آن دستور فقط برند را تغییر می‌دهد —
> نام سرویس، آدرس پشتیبانی و لوگو.

## انتخاب بدون ترمینال

`RT_TEMPLATE` فقط در **مسیر نصب** خوانده می‌شود. این یک متغیر محیطی است، پس اسکریپتی که به
آن اعمال می‌شود باید در دسترس باشد — یعنی عملاً باید `install.sh` را از یک **بستهٔ انتشار
بازشده** اجرا کنید:

```bash
RT_TEMPLATE=prism bash install.sh
```

با دستور یک‌خطی راه دور هم کار می‌کند، چون محیط به ارث می‌رسد:

```bash
RT_TEMPLATE=prism bash <(curl -fsSL https://github.com/frank0live/Row-Template/releases/latest/download/install.sh)
```

**روی نصب موجود اثری ندارد.** دستور `row-template config` آن را نمی‌خواند — برای جابه‌جایی
پس از نصب از مدیر استفاده کنید.

شناسه‌ای که در فهرست نباشد رد می‌شود و پیام خطا فهرست موارد موجود را نام می‌برد:

```
RT_TEMPLATE='xyz' is not a template this release offers (available: row editorial …)
```

**فهرست عمداً بسته است.** یک غلط تایپی نمی‌تواند بی‌صدا طرح دیگری نصب کند.

## انتخاب واقعاً چه می‌کند

نصب‌کننده **برای هر طرح یک فایل تأییدشده** در یک مخزن تمپلیت زیر ریشهٔ نصب نگه می‌دارد،
هرکدام با checksum خودش. انتخاب یک طرح، همان فایل را به‌عنوان صفحهٔ ارائه‌شده آماده می‌کند
و سپس صفحهٔ زنده را با آن هم‌تراز می‌کند.

چون هر فایل با checksum خودش تأیید می‌شود، انتخاب نمی‌تواند نیمه‌کاره بماند: یا طرح انتخابی
زنده است، یا وضعیت قبلی بازگردانده می‌شود.

## بعد از انتخاب چه انتظاری داشته باشید

```bash
row-template verify
```

بررسی، طرح انتخاب‌شده را گزارش می‌کند و تأیید می‌کند که صفحهٔ ارائه‌شده با آن مطابقت دارد:

```
Template: Row
Canonical artifact matches the selected template.
```

تنظیماتی که یک طرح را نام ببرد در حالی که طرح دیگری زنده است، تنها وضعیتی است که بررسی
هرگز نباید سالم گزارش کند — و آن را به‌عنوان شکست گزارش می‌کند.

## چطور بین‌شان انتخاب کنیم

راه صادقانهٔ مقایسه، ساختاری است نه رنگی.
[جدول مقایسه در گالری](/fa/templates/#مقایسه-بر-پایهٔ-ساختار) هر طرح را بر پایهٔ خانوادهٔ
چیدمان، ترکیب‌بندی، تراکم، گروه‌بندی و عرض فهرست می‌کند.

یک آزمون مفید: چون طرح‌ها ساختاری متفاوت‌اند، دیدنشان به‌صورت سیاه‌وسفید هم آن‌ها را از هم
جدا می‌کند.

## جابه‌جایی چه چیزی را تغییر نمی‌دهد

- **برند شما** — نام سرویس، لینک پشتیبانی و لوگو باقی می‌مانند.
- **داده‌های مشترکین شما.**
- **زمان اجرا، زبان‌ها و رفتار کد QR.**
