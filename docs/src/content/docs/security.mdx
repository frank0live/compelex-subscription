This page describes what Row-Template does, in terms you can check. It deliberately does
not claim more than the model delivers.

## Self-contained artifact

The served page is **one file**. It requests nothing from anywhere.

**Why it matters.** A page that fetches a font, a stylesheet or an analytics script is
broken offline, leaks the visitor's IP to a third party, and cannot be verified by
checksum — because its behaviour depends on something outside it.

**How to check it yourself.** Open the page with the network panel open. Nothing should
be requested. It renders identically with the network disabled.

## No CDN, no runtime dependency

CSS, JavaScript, the fonts and the QR generator are all inlined into the artifact at build
time. There is no remote asset, no external font, and no third-party service.

## Dangerous DOM APIs are forbidden

The build enforces a gate against the DOM APIs that turn a data value into code. The
artifact is generated only if the gate passes.

## Branding is data, never code

Your service name, support link and logo are stored **as data** and injected **as text**.
They are never executed.

The support link accepts only schemes a browser should open. A value containing control
characters, markup or a script fragment is **rejected**, not sanitised-and-hoped-for — the
installer refuses to generate a page from it and says why.

## Atomic replacement and rollback

The installer never edits a live file in place. Every replacement is staged, validated,
then swapped by **atomic rename**. Backups are kept, and the current version is
snapshotted before a rollback — so a failed rollback can itself be recovered.

If a step fails, the installer stops and leaves your existing setup untouched.

## No panel source patching

Row-Template **does not modify your panel**. No panel source file is patched.

- **3X-UI:** a single setting — the panel's *Sub Theme Directory* — pointed at a directory
  Row-Template creates.
- **PasarGuard:** one page file in the templates directory, and one marked block appended to
  `.env`. Your own lines are never edited. `.env` holds your secrets, so it is read only for
  the two page keys, never printed, and never copied into a backup.
- **Rebecca:** one page file, and the page and directory fields of the newest
  `subscription_settings` row. Only SQLite is written, only through `sqlite3`; a MySQL
  password is never asked for, read or printed.

Every change is snapshotted first and restored exactly if activation fails; uninstalling
reverts it and removes Row-Template's own files. Your users, inbounds, clients, nodes and
certificates are never touched.

On PasarGuard and Rebecca the page is a Jinja2 or pongo2 template. Every value it prints is
inside an explicit autoescape block — PasarGuard's Jinja2 does not escape by default — and
your branding enters the page with `{` and `}` escaped, so it can never open a template
tag.

## Template verification gates

- **Byte locks.** Every core template is pinned to an exact size and SHA-256. A one-byte
  change fails the test suite.
- **Deterministic builds.** The same sources always produce byte-identical output.
- **A structural contract.** 79 hooks exactly once, exactly three scripts, runtime and
  locale parity, and a single self-contained artifact within a fixed byte ceiling.

**What a byte lock proves.** It proves *integrity* — that the file is the approved file.
It does **not** prove *authorship*. It cannot tell you who produced it. That is what the
repository history and the release checksums are for.

## What this does not cover

- **Your subscription URL** is yours to protect. It is displayed by the page; it is not
  encrypted by it.
- **The server** is your responsibility — the panel's own hardening, TLS, and access
  control are outside Row-Template's scope.
- **This documentation site** is a normal website. The *artifact* is self-contained; the
  site you are reading is not the artifact.

## Reporting a vulnerability

Please report privately. See
[SECURITY.md](https://github.com/frank0live/Row-Template/blob/main/SECURITY.md). Do not
open a public issue for a security problem.
