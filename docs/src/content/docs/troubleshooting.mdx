Every entry here has four parts: the exact message, what it means, the likely causes, and
the fix. Entries are added only where the evidence exists in the source.

> **A note on refusals.** Several messages below are the installer **refusing to proceed**
> on purpose. They are safety mechanisms, not bugs. **Never work around one** — fix the
> cause it names. If a legitimate workflow needs to proceed despite a warning, that is a
> missing feature, not a missing workaround.

## Installation

### `3x-ui <version> is below the required minimum 3.6.0; not installing`

**What it means.** The installer checked your panel version and stopped before changing
anything.

**Causes.** 3X-UI is older than 3.6.0.

**Fix.** Update 3X-UI, then re-run the installer.

---

### `an existing install was found at …; re-run interactively or set RT_ASSUME_YES=1 to repair`

**What it means.** Row-Template is already installed at that path.

**Causes.** A previous install, or a partially completed one.

**Fix.** Run `row-template update` to move to the current release. To repair the existing
install in place, re-run with `RT_ASSUME_YES=1`.

---

### A checksum refusal

**What it means.** The downloaded archive did not match the fingerprint recorded when it
was released. The installer stopped before changing anything. Your existing setup is
untouched.

**Causes.** An incomplete download, transit corruption, or a file from somewhere other
than the official release.

**Fix.** Re-download from the official releases page and re-run. Verify the archive against
the published `SHA256SUMS`. **Do not bypass the check.**

---

### `unsupported image: only PNG, JPEG or WebP by content`

**What it means.** The logo file's actual bytes are not one of the accepted formats.

**Causes.** A different image format, or a file whose extension does not match its
contents.

**Fix.** Convert the logo to PNG, JPEG or WebP and re-run `row-template config`.

---

### `refusing to operate on a symlink: <path>`

**What it means.** The installer found a symbolic link where it expected a real file or
directory, and refused to write through it.

**Causes.** A symlinked install root, logo path, or managed file.

**Fix.** Use a real directory rather than a symlink. If you need the install elsewhere,
mount or bind it instead.

---

### `cannot determine the 3x-ui version; refusing to proceed`

**What it means.** The installer could not read the panel's version.

**Causes.** 3X-UI is not installed, is installed somewhere non-standard, or the panel's
files are not readable.

**Fix.** Confirm 3X-UI is installed and `x-ui` runs, then re-run.

## Template activation

### The subscription link still shows the panel's built-in page

**What it means.** The panel is not pointed at the Row-Template directory.

**Fix.** Set **Panel Settings → Subscription → Profile → Sub Theme Directory** to exactly:

```
/etc/3x-ui/sub_templates/row-template
```

Then reload the subscription link.

---

### PasarGuard still shows its own page

**What it means.** The Row-Template block in `/opt/pasarguard/.env` is not in effect, or
something in the panel takes precedence over it.

**Fix.** Run `row-template verify` as root. It names the cause:

- *the running panel does not use the Row-Template page yet (restart it)* — the panel was
  not restarted after activation. Run `pasarguard restart`.
- *N admin(s) set their own subscription page (sub_template)* — those admins' users keep
  that page. Clear the admin's subscription template in PasarGuard if you want them on
  Row-Template.
- *the panel's 'disable subscription template' setting is on* — PasarGuard serves the raw
  subscription to browsers. Turn the setting off in the panel.

---

### `panel pasarguard: <dir> is outside /var/lib/pasarguard, the directory the container shares with the host`

**What it means.** Your `CUSTOM_TEMPLATES_DIRECTORY` points outside the directory the
PasarGuard container can see, so a page placed there could never be served. Nothing was
changed.

**Fix.** Move your custom templates under `/var/lib/pasarguard`, update
`CUSTOM_TEMPLATES_DIRECTORY`, and re-run.

---

### `the Row-Template block in .env is damaged`

**What it means.** Only one of the block's two marker lines is in `/opt/pasarguard/.env`,
so the installer cannot tell where its block ends. It refuses rather than guess.

**Fix.** Remove the remaining `# >>> row-template` or `# <<< row-template <<<` line (and the
two keys between them, if any) by hand, then re-run.

---

### Rebecca: *One manual step remains*

**What it means.** Rebecca uses MySQL/MariaDB, or `sqlite3` is not installed, so the
installer placed the page but could not select it.

**Fix.** Install `sqlite3` and run `row-template` → **Activate**, or select it yourself in
**Settings → Subscription → Templates**: *Subscription page template*
`row-template/index.html`, *Custom templates directory* `/var/lib/rebecca/templates`.

---

### `panel rebecca: this is Rebecca 0.0.x, the Python edition …`

**What it means.** This Rebecca runs Docker Hub's `rebeccapanel/rebecca` image, which is
still the 0.0.x Python edition. It cannot render Row-Template's Rebecca page, so the
installer refused before changing anything.

**Fix.** Move to Rebecca 1.x, the Go edition, with Rebecca's own `rebecca migrate-binary`
(or install it with `rebecca-binary.sh`), then re-run the installer.

---

### Some Rebecca users still see another page

**What it means.** `row-template verify` reports *N admin(s) override the subscription page
for their own users*. Rebecca lets an admin choose a page for their own users; those users
keep it.

**Fix.** Clear that admin's subscription template settings in Rebecca if you want their
users on Row-Template.

---

### `<path> exists and is not Row-Template's; it was left untouched`

**What it means.** A file that Row-Template did not write is at the path it places its page
(`…/templates/row-template/index.html`). It is never overwritten, and the activation was
rolled back.

**Fix.** Move that file elsewhere, then re-run.

## Live status

### `Live check could not reach the subscription endpoint.`

**What it means.** `row-template verify` tried to fetch the live page and could not.

**Causes.** A network restriction, a proxy in the way, or the panel not being reachable
from the server itself.

**Fix.** This is a **warning, not a failure**. The server-rendered values still work. Check
that the panel answers locally, then re-run `row-template verify`.

---

### The figures do not refresh on PasarGuard or Rebecca

**What it means.** This is expected. Both panels serve live status on a path suffix rather
than `?format=info`, so the page shows the values as of when it was opened. Reload the page
to update them. See [Compatibility](/compatibility/#known-limits).

## Build and verification

### A test reports a changed size or checksum

**What it means.** A template artifact no longer matches its byte lock.

**Causes.** A source change that was not accompanied by an intentional lock update.

**Fix.** If the change was deliberate, update the lock in the same commit. If it was not,
revert the change. **A lock update is a reviewed event, not a formality.**

## Update and rollback

### `No templates are installed` (Reconfigure branding → Template)

**What it means.** The manager found no designs in the template store, `dist/templates/`
under the install root.

**Causes.** An update from 1.1.0: 1.1.0's own updater copies only part of the new release.
Since 1.2.1 the manager downloads the missing designs itself when it opens, so this appears
only when that download failed; the message above it says why.

**Fix.** Make sure the server can reach the release source, then open the menu again, or run
`row-template update`.

---

### `template store is incomplete (<n> of <total> designs); missing: …`

**What it means.** `row-template verify` found designs missing from the store. Every
installed design still works; the missing ones are not offered in the manager.

**Fix.** Run `row-template verify` as root with the release source reachable, or run
`row-template update`.

---

### `Template store: moved <n> design(s) from …/templates to …/dist/templates`

**What it means.** Designs were found in a `templates/` folder at the install root — where a
copied or extracted release leaves them — instead of in `dist/templates/`. Each one passed
its checksum and was moved into place. There is nothing to do.

---

### `refusing to roll back from a path outside the backups tree`

**What it means.** The rollback was asked to restore from a directory that is not a
Row-Template backup.

**Fix.** Use `row-template rollback --auto`, or `--to` with a directory the installer
created.

---

### `refusing to delete <root>: it does not look like a Row-Template install root`

**What it means.** The uninstaller checked the directory and did not recognise it as its
own.

**Fix.** This is a guard against deleting the wrong directory. Confirm the install root is
`/etc/3x-ui/sub_templates/row-template` (3X-UI) or `/etc/row-template` (PasarGuard,
Rebecca), then re-run.

## Browser and display

### Flags render as letters on Windows

**What it means.** Windows Chromium has no local font containing flag glyphs, so the
country badge falls back to the two-letter code.

**Status.** **Known and documented.** This is a platform limitation, not a defect, and it
is one of the open questions in the flag-rendering workstream. The badge is legible either
way.

## Still stuck

```bash
row-template version
row-template verify
```

Include both outputs when you open an issue.

> **Do not include secrets.** Never paste subscription URLs, `subId` values, client UUIDs,
> panel credentials, cookies, tokens, the panel `webBasePath`, the contents of `.env`,
> database URLs, TLS keys, or real server addresses. Redact logs before sharing them.
